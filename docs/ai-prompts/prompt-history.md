## 1. 项目概览

### 1.1 产品目标

用一份带有大学生生活气息的 Mock 消费数据，构建一个可直接在浏览器打开的单文件赛博玄学看板：

- 用 ECharts 展示消费地点、深夜消费与每日趋势。
- 支持用户上传自己的 CSV，覆盖默认 Mock 数据。
- 根据消费与选课数据，用本地规则引擎生成可解释的“赛博人设 + 运势报告”。
- 兼顾桌面端与手机端，支持随手记一笔并立即刷新数据与运势。

### 1.2 技术选型

| 层级 | 方案 |
| --- | --- |
| 页面 | 原生 HTML / CSS / JavaScript，单文件 `index.html` |
| 样式 | Tailwind CSS CDN + 自定义赛博霓虹样式 |
| 图表 | ECharts 5.4.3 CDN |
| 数据导入 | 浏览器 `FileReader`，UTF-8 CSV |
| 数据来源 | 内置 Mock 数据、上传 CSV、手机快捷记账追加 |
| AI 解读 | 本地“规则引擎 + 模拟大模型 JSON”，不依赖真实后端 |

## 2. 迭代 1：数据解析与图表

### 2.1 阶段目标

把静态 Mock 数据升级为“可导入、可校验、可自适应展示”的消费数据大盘。

核心要求：

1. 保留默认 Mock 数据，页面打开即可展示。
2. 支持拖拽或点击上传 CSV，最大 2 MB。
3. 上传成功后替换当前数据，并刷新图表和玄学报告。
4. 兼容简单四列 CSV 和复杂多列 CSV。
5. 缺少可选字段时，不伪造数据，图表与文案自动降级。

### 2.2 核心 Prompt

#### Prompt 1：加入 CSV 导入与动态图表

```text
请在现有单文件 index.html 中加入 CSV 自定义数据导入区域。

要求：
1. 支持拖拽和点击选择文件，仅接受 .csv，最大 2 MB；
2. 用 FileReader 读取 UTF-8 内容，解析消费流水；
3. 上传成功后替换当前 EXPENSES 数据，重新渲染两个 ECharts 图表；
4. 同时重新生成 AI 玄学报告；
5. 提供“恢复 Mock 数据”按钮；
6. 未上传时继续使用内置 Mock 数据，不影响首次打开体验。
```

#### Prompt 2：放宽字段要求并自适应降级

```text
请放宽 CSV 解析与校验规则。

- 必需列只有：date（或 data）、category、amount；
- time、location、note / remark 都是可选列；
- 日期兼容 YYYY-MM-DD、YYYY/M/D、YYYY.M.D，并统一输出 YYYY-MM-DD；
- 金额需要清理 ¥、￥、逗号和空格；
- 缺少 time / location 时保留空字符串，不要伪造“未知地点”等默认值；
- 图表和 AI 文案必须根据实际可用字段自动适配；
- 无效行跳过，并在上传状态中给出可读的错误提示。
```

#### Prompt 3：图表必须由当前数据派生

```text
图表不要写死 Mock 数据。

请让两个图表都从当前 EXPENSES 实时派生：
1. 有 location 时按地点统计消费占比；没有 location 时降级为 category 消费构成；
2. 有深夜或夜宵记录时展示夜宵趋势；没有 time 相关记录时降级为每日消费趋势；
3. 图表标题、空数据提示和 tooltip 都要随数据字段变化；
4. 上传 CSV、追加记账、恢复 Mock 后都复用同一套图表刷新逻辑。
```

### 2.3 交互过程

1. 先明确“默认可用、上传覆盖”的数据流，避免页面初始化依赖远程文件。
2. AI 实现基础 CSV 上传、状态提示和 ECharts 刷新。
3. 用户补充真实使用场景：手机导出的账单列数不固定，只有日期、分类、金额是稳定字段。
4. AI 重构解析器，将字段识别改为表头映射，并允许 `date` / `data`、`remark` / `note` 兼容。
5. 针对缺失字段，用户明确要求“不强行设置默认值”，AI 将 `time`、`location` 保留为空，并新增自适应图表标题与 AI 证据文案。
6. 补充无效行统计、错误样例、BOM 清理、金额清洗和 CSV 引号字段处理。

### 2.4 AI 协作成果

#### 数据解析能力

- 解析前移除 UTF-8 BOM，兼容 CRLF / LF。
- 表头统一去空格并转小写。
- 必需列：`date` / `data`、`category`、`amount`。
- 可选列：`time`、`location`、`note` / `remark`。
- 日期支持 `YYYY-MM-DD`、`YYYY/M/D`、`YYYY.M.D`，并校验日期真实存在。
- 金额支持 `¥`、`￥`、逗号和空格清理。
- 支持 CSV 引号字段与备注中的逗号。
- 无效行计入 `skipped`，最多保留 3 条 `errorSamples`。
- 返回 `columns` 元信息，供上传提示和图表适配使用。

#### 图表与数据流

- 新增 `buildLocationOption()`：地点优先，缺失时降级为分类饼图。
- 新增 `buildNightOption()`：夜宵/深夜优先，否则展示每日消费趋势。
- 新增 `updateExpenseCharts()`：统一刷新图表与动态标题。
- 图表空数据时显示 `graphic` 提示，而不是渲染空白画布。
- `applyExpenseData()` 统一处理上传 CSV、恢复 Mock 和后续数据变更。
- 上传状态会提示缺失的可选列，并说明相关视图已自动适配。

| 图表标题与图形随字段自适应 | 支持 |

## 3. 迭代 2：玄学逻辑与人设

### 3.1 阶段目标

把普通消费图表升级成一个“有数据依据的娱乐型 AI 玄学终端”：

- 结论必须由消费与选课数据推导，而不是纯随机文案。
- 输出结构固定，便于前端渲染和未来替换真实大模型接口。
- 视觉上保持赛博朋克、暗黑科技和终端扫描线风格。
- 明确娱乐属性，不构成真实消费、选课或医疗建议。

### 3.2 核心 Prompt

#### Prompt 1：生成校园生活 Mock 数据

```text
请生成一组符合大学生生活特征的 Mock 数据，用于赛博玄学消费看板。

消费数据包含：
date,time,location,category,amount,remark

场景要覆盖食堂、校园超市、奶茶店、夜宵、期末周囤货等；
再生成一份课程数据，包含课程名、学分、成绩、难度评分和备注，
让消费与课程之间可以形成“熬夜渡劫 / 奶茶续命 / 期末硬刚”的叙事关联。
```

#### Prompt 2：实现 AI 玄学解读卡片

```text
请继续实现“AI 趣味玄学解读终端”。

要求：
1. 结合消费流水和课程数据，生成运势分数、赛博人设、证据链、行动指南和开运参数；
2. 用本地规则引擎模拟大模型，返回值保持 JSON 结构，方便以后替换成真实接口；
3. 所有结论都要能追溯到具体字段或统计结果；
4. 增加终端加载动画、打字机效果和“重新卜一卦”交互；
5. 使用 Tailwind + 霓虹紫/青色、网格、扫描线，保持赛博暗黑风格；
6. 页面底部注明仅供娱乐，不构成真实建议。
```

#### Prompt 3：保证事实可解释，禁止硬编结论

```text
玄学文案可以夸张，但事实不能编造。

请先计算事实，再生成人设和报告：
- 深夜订单数、深夜金额、奶茶杯数、期末周消费、最常消费地点、最难课程；
- 如果没有 time 字段，就明确说明无法判定深夜行为；
- 如果没有 location 字段，就明确说明无法判断消费磁场；
- 随机性只用于文案模板和运势波动，不改变底层事实。
```

### 3.3 交互过程

1. 用户先确定“娱乐向玄学”而非真实预测，要求结论有趣、有梗、可解释。
2. AI 设计 `analyzeCampusData()` 作为事实层，将流水和课程转换为统一统计对象。
3. AI 设计 `buildDivination()` 作为规则引擎，输出固定 JSON 结构。
4. 用户补充视觉要求，AI 加入塔罗式分数环、霓虹网格、扫描线、终端日志、证据链和开运参数。
5. 用户要求“重新卜一卦”不能只是换文案，AI 保留事实不变，仅对运势波动、卦象和文案模板做可控随机。
6. 在 CSV 支持可选字段后，AI 再次调整报告：缺失 `time` / `location` 时显示“未提供字段”，不再生成虚假的深夜或地点结论。

### 3.4 AI 协作成果

#### 数据分析层

`analyzeCampusData()` 统一输出：

- 总记录数、总金额。
- `hasTime`、`hasLocation` 字段可用性。
- 深夜记录数、深夜金额。
- 夜宵记录、奶茶记录与金额。
- 期末周记录数与金额。
- 最高频消费地点（无地点时为 `null`）。
- 最难课程（按难度降序、成绩升序）。

#### 规则引擎与人设

- 运势分数由熬夜、奶茶、期末消费、课程难度和随机波动共同计算，并限制在 32–98。
- 人设覆盖：
  - 深夜渡劫型 · 奶茶续命法师
  - 月相绑定型 · 凌晨灵能者
  - 期末硬刚型 · 渡劫苦行僧
  - 硬核选课型 · 难度收集者
  - 平稳摸鱼型 · 低耗能散修
- 报告输出包含：
  - `persona`：人设标题、代号、标签、描述。
  - `score` / `tier`：运势分数与等级。
  - `reportLines`：分段解读文案。
  - `evidence`：数据证据链。
  - `actions`：今日行动指南。
  - `lucky`：开运参数。
  - `auraStats`：熬夜、糖分、渡劫、财库四维能量条。
  - `warning`：娱乐免责声明。

#### 前端呈现与交互

- 终端启动日志逐行输出。
- 报告正文打字机效果，支持“跳过/立即完成”。
- 运势环从 0 动画到目标分数。
- `prefers-reduced-motion` 下关闭动画，保证可访问性。
- 所有用户文本通过 `escapeHTML()` 转义后渲染。
- 缺失可选字段时，报告改用日期、分类、金额维度推演。

### 3.5 阶段验收点

| 验收项 | 结果 |
| --- | --- |
| 报告结论来自消费/课程统计 | 支持 |
| 固定 JSON 输出结构 | 支持 |
| “重新卜一卦”保留事实、改变文案与波动 | 支持 |
| 缺失 `time` / `location` 时不编造结论 | 支持 |
| 终端动画与赛博视觉风格 | 支持 |

## 5. 协作复盘

### 5.1 有效的协作方式

1. **用户定义业务规则，AI 负责拆解与实现**  
   用户更清楚“大学生消费场景”和验收标准，AI 负责数据结构、图表配置、交互和样式落地。

2. **先事实、后叙事**  
   玄学文案可以夸张，但深夜订单、奶茶杯数、期末消费等事实必须先计算，避免“看起来像 AI，实际全靠编”。

3. **显式字段契约**  
   明确必需列与可选列，缺失字段保留空值并让视图降级，比悄悄补默认值更可靠。

4. **复用单一数据管线**  
   上传 CSV、恢复 Mock、快捷记账都走同一套 `applyExpenseData` / 图表刷新 / 报告重算路径，减少行为分叉。

5. **增量迭代，持续回归**  
   每次都保留既有功能：新增 CSV 不破坏 Mock，新增可选字段不破坏复杂 CSV，新增移动端表单不破坏桌面端。

### 5.2 AI 在项目中的角色

| 角色 | 具体工作 |
| --- | --- |
| 产品拆解 | 将“赛博玄学看板”拆成数据、图表、规则引擎、交互、响应式、部署六层 |
| 数据工程 | CSV 解析、字段映射、日期/金额清洗、无效行统计、可选字段降级 |

### 5.4 后续可继续的 Prompt 方向

- **数据持久化**：把快捷记账结果写入 `localStorage`，刷新页面后仍保留。
- **CSV 模板下载**：提供四列模板下载链接，降低用户准备文件的成本。
- **字段补全**：为快捷记账增加可选地点/时间，让新增记录也能进入地点饼图与深夜曲线。
- **真实模型接入**：用 `fetch('/api/divination')` 替换本地规则引擎，保持现有 JSON 契约不变。
- **自动化验收**：增加 CSV 解析单元测试和移动端浏览器测试。
- **工程化拆分**：当功能继续增长时，将内联脚本拆分为模块，同时保留静态部署能力。

## 6. 可复用的 Prompt 模板

后续新增需求时，可以继续使用以下结构，让 AI 输出更稳定：

```text
【背景】
当前项目是……，现有数据字段是……，已有功能是……。

【目标】
请新增/修改……，用户使用场景是……。

【约束】
- 必须保持……不变；
- 缺少……时不要伪造默认值；
- 复用现有的……函数/数据流；
- 保持桌面端与手机端可用；
- 使用现有技术栈，不引入不必要依赖。

【交互】
点击……后，执行……，并给出……反馈。

【验收】
1. ……
2. ……
3. ……
```

---

> 本文档用于记录人与 AI 的协作过程，不替代逐字聊天记录。若后续需求变更，建议按“新增迭代”追加，而不是覆盖历史阶段。
